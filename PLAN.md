# PLAN.md

Roadmap to evolve this repo from a scripts-and-notes scaffold into a **Claude Code Skill** that an agent invokes to produce a background-music / ambient-soundscape WAV file.

This plan is **carefully sequenced**: every milestone is shippable on its own, every milestone leaves the repo green (tests + lint + docs), and every milestone is small enough to land in one focused session. It is binding — deviations need a HISTORY.md note.

Companion docs: [SWED.md](SWED.md) (engineering rules), [docs/guide.md](docs/guide.md) (the underlying pipeline), [AGENTS.md](AGENTS.md) (agent roles).

---

## 1. Goal

Deliver a **Skill** (in the Anthropic skill format) named something like `soundscape-gen` that:

- **Triggers** when a user asks for background music, ambient audio, a soundscape for a video, etc.
- **Inputs**: mood description, duration, optional key/scale/tempo/avoid/include hints, output path.
- **Outputs**: a 24-bit WAV file at the requested path, normalized to −6 dBFS, plus a sidecar `.json` describing the pattern, tempo, orbits, and render settings (for reproducibility).
- **Works locally** on macOS, Linux, Windows native, and Windows-via-WSL.
- **Is honest about prerequisites**: detects missing SuperCollider / SuperDirt / Strudel and surfaces an actionable install message instead of failing opaquely.

## 2. Non-goals (v1)

- No cloud rendering. Everything runs on the user's machine.
- No real-time interactive editing — the skill produces a finished file, not a live session.
- No DAW integration, no MIDI input, no video processing.
- No custom sample-pack management UI — users point at a folder, that's it.
- No model-side audio generation (no diffusion models, no Suno, no MusicGen). This skill is purely a Strudel/SuperDirt orchestrator.

## 3. Architectural decisions

| Decision | Choice | Rationale |
|---|---|---|
| Orchestration language | **Python 3.11+** | Matches Anthropic skill conventions; rich subprocess + path libs; cleanest cross-platform story; easiest `pytest`/`pytest-bdd` setup. |
| CLI framework | **Typer** | Pydantic-native, auto-generates `--help`, good for both human and skill use. |
| Subprocess control | `subprocess.run` with `list[str]` args, `shell=False` | Cross-platform safety; no injection surface. |
| OSC | Reuse Strudel's existing `pnpm run osc` bridge in v1 | Don't reimplement what Strudel ships. Revisit if startup latency hurts. |
| SC interaction | Spawn `sclang` with a generated `.scd` file | Stateless per-render; survives SC crashes between renders. |
| Pattern files | Strudel `.js`, generated by template + LLM-authored body | Templates enforce orbit/slow/room conventions from SWED §2. |
| Output format | 24-bit WAV, 48 kHz, stereo (mono mixdown optional) | Video-editor friendly; per guide §8. |
| State/log dirs | `platformdirs` | XDG on Linux, `~/Library/Application Support` on macOS, `%LOCALAPPDATA%` on Windows. |

If any of these prove wrong, change the decision **here** in PLAN.md with a HISTORY entry — don't let two truths coexist.

## 5. Milestones

Each milestone is **a single PR**, ending green. The order matters — don't reorder without updating dependencies.

### M0 — Repo hygiene (½ day)

**Outcome:** repo is on GitHub, CI green, linters live.

- `git init`, initial commit of current scaffold.
- `gh repo create strudel-gen --public --source=. --push`.
- Add `pyproject.toml` with ruff + mypy + pytest config.
- Add `.pre-commit-config.yaml` and install hooks.
- Add `.github/workflows/ci.yml` running ruff + mypy + pytest on macOS/Ubuntu/Windows.
- Add `.gitignore`, `.gitattributes`.
- README "Status" badge.

**Done when:** `gh repo view --web` shows green CI on a no-op PR.

### M1 — Python skeleton + detection (1 day)

**Outcome:** `strudel-gen doctor` reports which prerequisites are present on the current machine.

- Create `src/strudel_gen/` package.
- `detect.py`: locate `sclang`, `node`, `pnpm`, the Strudel clone dir (env var `STRUDEL_DIR`), detect OS + WSL.
- `cli.py`: Typer app with `doctor` subcommand.
- `logging_setup.py`: file-based rotating logs to platformdirs state dir.
- Unit tests with mocked `shutil.which` and `platform` for all 4 OS targets.
- BDD feature: `features/doctor.feature` — "Given SC is installed, When I run doctor, Then it reports OK".

**Done when:** `strudel-gen doctor` runs on mac and reports honest status; tests green.

### M2 — Pattern model + renderer (1 day)

**Outcome:** Python can take a `PatternSpec` (Pydantic) and emit a valid Strudel `.js` file that respects SWED conventions (orbit, slow, room).

- `patterns/model.py`: `PatternSpec`, `Layer`, `Effect` Pydantic models.
- `patterns/render.py`: Jinja-based renderer; templates for drone / sci-fi / nature mood families (from guide §5.2).
- Snapshot tests: given fixture specs, output matches golden `.js` files.
- Property test: every rendered file passes a structural check (has `setcpm`, `stack`, every layer has `.slow()≥4` and `.room()≥0.7`).

**Done when:** `strudel-gen render-pattern --spec spec.json --out pattern.js` produces a file that runs in the Strudel REPL.

### M3 — Bridge + SC lifecycle (1 day)

**Outcome:** Python can start the OSC bridge and a SuperCollider process with the project startup file, verify SuperDirt is listening, and shut both down cleanly.

- `bridge.py`: spawn `pnpm run osc`, capture stdout/stderr, detect "listening on" line, expose context manager.
- `sc.py`: spawn `sclang` with `-D` (daemon) or interactive, evaluate the startup `.scd`, watch post output for the SuperDirt ready marker.
- Both wrapped in `with`-statements so SIGINT cleanup is reliable.
- Integration tests: skipped if `sclang`/`pnpm` missing; otherwise actually boot and tear down.
- BDD: `features/bridge.feature`.

**Done when:** `strudel-gen session --dry-run` boots SC + bridge, waits 3s, tears down, with full logs in the log file.

### M4 — Record orchestration (1 day)

**Outcome:** end-to-end render — given a `PatternSpec` and duration, produce a `.wav`.

- `recorder.py`: generate a `Routine` script that (1) evaluates the pattern via OSC, (2) calls `s.record` with WAV/int24, (3) waits, (4) calls `s.stopRecording`.
- `normalize.py`: post-process with `ffmpeg -filter:a loudnorm` to −6 dBFS; emit sidecar JSON.
- CLI: `strudel-gen render --mood "..." --duration 240 --out song.wav`.
- Acceptance test (slow, opt-in): renders a 10-second drone, asserts file exists, is WAV, is ≥9.5s long, RMS is non-silent.

**Done when:** a real WAV lands on disk that an audio player can open and that sounds like the requested mood.

### M5 — Skill packaging (½ day)

**Outcome:** the Claude Code skill exists and is invokable.

- `skill/SKILL.md`: name, description (the trigger), `Allowed-Tools: Bash`, instructions that map user intent → `strudel-gen render` invocation.
- Skill description carefully tuned per Anthropic skill conventions (the description IS the trigger).
- Example transcripts in `docs/skill-usage.md`.
- Skill validated end-to-end: open Claude Code, ask for "background music for a 2-minute calming meditation video", verify the skill fires and produces a file.

**Done when:** in a fresh Claude Code session, asking for a soundscape triggers the skill without explicit `/` invocation.

### M6 — Cross-platform validation (1 day)

**Outcome:** the skill is verified on all four target platforms.

- Manual run-through on: macOS (already primary), Ubuntu 22.04, Windows 11 native, Windows 11 + WSL2 Ubuntu.
- WSL2 specifically: document the audio routing constraint (SC runs on Windows host, WSL only orchestrates) OR drop WSL support with a documented reason.
- CI matrix flips to required.
- `docs/troubleshooting.md` updated with the bugs found.

**Done when:** all four platforms have a green checklist in HISTORY.md.

### M7 — Multi-stem rendering (stretch, 1 day)

**Outcome:** opt-in `--stems` flag produces per-orbit WAVs for DAW post.

- Per guide §4.4: 6-channel record, ffmpeg split.
- Sidecar JSON lists stem-to-orbit-to-layer mapping.

### M8 — Pattern library + presets (stretch, ongoing)

**Outcome:** curated `src/patterns/` library + Python-side presets users can request by name (`--preset cold-underwater`).

## 6. Risks & mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| SC startup latency makes per-render boot feel slow | High | Keep one SC instance warm across renders in a daemon mode (M7+). |
| WSL audio routing impossible in practice | Medium | Document early (M1 doctor warns); fall back to "run from Windows host" instructions. |
| Strudel internal API changes break the OSC bridge | Medium | Pin Strudel to a known-good commit in `detect.py`; CI fetches that pin. |
| `ffmpeg` not installed | Medium | Vendor as optional; if absent, skip normalization with a WARNING and ship raw WAV. |
| Skill description fires too eagerly (any "music" request) | Medium | Tight description: "ambient/background soundscape, locally rendered via Strudel/SuperCollider". User-testable in M5. |
| LLM-generated patterns produce inaudible or broken JS | High | M2 structural validator + dry-eval (Node syntax check) before passing to Strudel. |
| Copyright on Dirt-Samples for distributed output | Low | Document license; default render uses synth-only sources unless user opts in. |

## 8. How we measure success

- A new user can go from `gh repo clone` → first rendered WAV in **under 30 minutes** on a supported platform.
- Asking a Claude Code session "make me 3 minutes of cold underwater ambience" produces a usable file with **zero follow-up questions** in the happy path.
- CI green on all four platforms continuously for **two weeks** before declaring v1.
